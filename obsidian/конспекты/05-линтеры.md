# Линтеры и статический анализ в Python

## 1. Что такое линтеры и статический анализ

Линтер - это инструмент статического анализа, который проверяет исходный код без его запуска. Он помогает находить ошибки, подозрительные конструкции и нарушения принятых правил оформления кода.

Линтеры позволяют обнаруживать проблемы ещё во время разработки. Это помогает поддерживать единый стиль проекта, уменьшать количество ошибок и не допускать некачественный код в репозиторий.

Например, линтер может обнаружить:

1) неиспользуемые импорты;

2) неиспользуемые переменные;

3) нарушения стиля;

4) слишком длинные строки;

5) подозрительные конструкции;

6) некоторые потенциальные ошибки.

Важно отличать линтер от форматера. Линтер в первую очередь ищет проблемы в коде, а форматер автоматически приводит код к единому виду.

## 2. Основные инструменты для Python

В экосистеме Python существует несколько популярных инструментов для проверки и форматирования кода.

| Инструмент | Основное назначение |
|---|---|
| **Ruff** | Линтинг и форматирование |
| **Black** | Автоматическое форматирование |
| **Flake8** | Линтинг и проверка стиля |
| **Pylint** | Более глубокий анализ качества кода |
| **isort** | Сортировка импортов |
| **mypy** | Статическая проверка типов |

Пройдемся немного по второстепенным  и остановимся на главном.

### Black

**Black** - форматер Python-кода. Он автоматически приводит код к единому стилю.

```bash
pip install black
black file.py
```

Проверить форматирование без изменения файлов можно с помощью:

```bash
black file.py --check
```

Также ,если добавить -diff ,то мы увидим что именно изменил black.

```bash
black file.py --check --diff
```

Пример вывода:

```diff
--- file.py	2024-01-01 12:00:00
+++ file.py	2024-01-01 12:00:01
@@ -1,3 +1,3 @@
-def  add( a,b ):
-    x= a+b
+def add(a, b):
+    x = a + b
     return x
would reformat file.py

Oh no! 💥 💔 💥
1 file would be reformatted.
```



### Flake8

**Flake8** - классический линтер, который объединяет несколько проверок стиля и потенциальных проблем.

```bash
pip install flake8
flake8 file.py
```

Пример вывода:

```bash
file.py:5:5: E225 missing whitespace around operator
file.py:5:5: E271 multiple spaces after keyword
file.py:5:5: E201 whitespace after '('
file.py:5:5: E231 missing whitespace after ','
file.py:5:5: E202 whitespace before ')'
file.py:6:5: E225 missing whitespace around operator
file.py:9:1: F841 local variable 'res' is assigned to but never used
```



### Pylint

**Pylint** - выполняет более подробный анализ кода: проверяет стиль, имена переменных, структуру программы и некоторые потенциальные проблемы.

```bash
pip install pylint
pylint file.py
```

Пусть исходный код:

```python
import sys
import os

def  calc( a,b ):
    x= a+b
    return x

result = 1
```

Пример вывода:

```diff	
file.py:1:1: F401 'sys' imported but unused
file.py:2:1: F401 'os' imported but unused
file.py:4:1: E302 expected 2 blank lines, found 1
file.py:4:7: E201 whitespace after '('
file.py:4:9: E231 missing whitespace after ','
file.py:5:5: E225 missing whitespace around operator
file.py:8:1: E305 expected 2 blank lines after class or function definition, found 1
```

### Isort

**Isort** - автоматически сортирует импорты.

```bash
pip install isort
isort file.py
```

Было:

```python
from typing import List
import sys
import requests
import os
from myproject import utils
import json
from django.db import models
```

Стало:

```python
import json
import os
import sys
from typing import List

import requests
from django.db import models

from myproject import utils
```



### mypy

**mypy** - предназначен для статической проверки типов.

```python
def add(a: int, b: int) -> int:
    return a + b
result = add("hello", "world")
```

Если вызвать функцию с неподходящими типами, mypy может обнаружить такую проблему ещё до запуска программы.

```bash
pip install mypy
mypy file.py
```

Пример вывода:

```bash
file.py:4: error: Argument 1 to "add" has incompatible type "str"; expected "int"  [arg-type]
file.py:4: error: Argument 2 to "add" has incompatible type "str"; expected "int"  [arg-type]
Found 2 errors in 1 file (checked 1 source file)
```



## 3. Ruff - современный инструмент для Python

**Ruff** - быстрый линтер и форматер для Python, разработанный компанией Astral.

Одно из его главных преимуществ - высокая скорость работы. Кроме того, Ruff позволяет заменить несколько отдельных инструментов в небольших и средних проектах.

Например, вместо использования нескольких инструментов:

```text
Flake8 -> линтинг
Black  -> форматирование
isort  -> сортировка импортов
```

можно использовать Ruff:

```text
Ruff -> линтинг
Ruff -> форматирование
```

### Установка

```bash
pip install ruff
```

### Основные команды

Проверка кода:

```bash
ruff check file.py
```

Автоматическое исправление найденных проблем:

```bash
ruff check file.py --fix
```

Форматирование:

```bash
ruff format file.py
```

## 4. Пример работы Ruff

Рассмотрим небольшой Python-скрипт:

```python
import os
import sys


def hello(text):
    unused = 10
    print(  "Hello, " + text )


hello("World")
```

В этом коде есть несколько проблем:

1) `os` не используется;

2) `sys` не используется;

3) переменная `unused` не используется;

4) форматирование `print()` выполнено некорректно;

5) функция и код могут быть отформатированы более единообразно.

Запустим:

```bash
ruff check main.py
```

Ruff сообщит о найденных проблемах:

```bash
file.py:1:8: F401 [*] `os` imported but unused
file.py:2:8: F401 [*] `sys` imported but unused
file.py:6:5: F841 [*] Local variable `unused` is assigned to but never used
file.py:7:11: E211 [*] Whitespace before '('
file.py:7:12: E201 [*] Whitespace after '('
file.py:7:32: E202 [*] Whitespace before ')'
Found 6 errors.
[*] 5 fixable with the `--fix` option.
```

Часть из них можно исправить автоматически:

```bash
ruff check main.py --fix
```

```bash
Found 6 errors (5 fixed, 1 remaining).
file.py:7:11: E211 Whitespace before '('
```

После этого можно запустить форматтер:

```bash
ruff format main.py
```

В результате код будет приведён к более аккуратному виду, а исправляемые автоматически проблемы будут устранены:

Таким образом, разработчику не приходится вручную искать каждую проблему.

## 5. Конфигурация линтера

Настройки Ruff можно хранить в файле `pyproject.toml`. Это позволяет задать правила, которые будут использоваться во всём проекте.

Пример конфигурации:

```toml
[tool.ruff]
line-length = 88
target-version = "py312"

[tool.ruff.lint]
select = [
    "E",
    "F",
    "I",
]
```

### Основные настройки

```toml
line-length = 67
```

Максимальная длина строки.

```toml
target-version = "py312"
```

Версия Python, под которую выполняется анализ.

```toml
select = ["E", "F", "I"]
```

Выбор групп правил:

1) `E` - проверки стиля;

2) `F` - обнаружение некоторых ошибок и неиспользуемого кода;

3) `I` - проверки импортов.

При необходимости отдельные правила можно отключить:

```toml
[tool.ruff.lint]
select = ["E", "F", "I"]
ignore = ["E501"]
```

Такой подход удобен тем, что все разработчики проекта используют одинаковые настройки.

## 6. Pre-commit

**pre-commit** - инструмент, который позволяет автоматически запускать проверки перед созданием Git-коммита.

Без него разработчику нужно самостоятельно выполнять команды:

```bash
ruff check file.py
ruff format file.py
```

Перед каждым коммитом.

С `pre-commit` этот процесс автоматизируется:

```text
 git commit
     |
     V
 pre-commit
     |
     V
 ruff check
     |
     V
 ruff format
     |
     V
   commit
```

Если проверка обнаруживает проблему, commit может быть остановлен до её исправления.

### Установка

```bash
pip install pre-commit
```

После установки нужно добавить конфигурацию и установить Git hooks:

```bash
pre-commit install
```

После этого pre-commit будет запускаться автоматически при выполнении `git commit`.

## 7. Конфигурация Ruff + pre-commit

Для настройки pre-commit создаётся файл:

```text
.pre-commit-config.yaml
```

Пример конфигурации:

```yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.12.0
    hooks:
      - id: ruff-check
        args: [--fix]

      - id: ruff-format
```

В данной конфигурации используются два hook:

*Hook  - это автоматическое действие, которое запускается в определённый момент работы с Git.

### ruff-check

```yaml
- id: ruff-check
  args: [--fix]
```

Запускает линтер Ruff и разрешает ему автоматически исправлять те проблемы, которые поддерживают автоматическое исправление.

### ruff-format

```yaml
- id: ruff-format
```

Запускает форматер Ruff.

### Как это работает

После настройки достаточно выполнить:

```bash
git add file.py
git commit -m "add new feature"
```

Перед созданием коммита автоматически запускаются проверки:

```text
git commit
    |
    V
pre-commit
    |
    V
ruff-check     
    |
    V
ruff-format     
    |
    V
  успешно?
   /    \
  V      V
 да     нет
 |       |
 V       V
commit  commit
        остановлен
```

Таким образом, pre-commit помогает не допускать в репозиторий код, который не соответствует установленным правилам.

При изменении проекта можно добавить и другие проверки, например `mypy` или запуск тестов.

## 8. Вывод

Линтеры и инструменты статического анализа позволяют находить проблемы в Python-коде ещё до его запуска и помогают поддерживать единый стиль проекта.

Разные инструменты решают разные задачи:

```text
Black  -> форматирование
Flake8 -> линтинг
isort  -> сортировка импортов
Pylint -> анализ качества кода
mypy   -> проверка типов
Ruff   -> линтинг + форматирование
pre-commit -> автоматический запуск проверок
```

Для современного Python-проекта удобным минимальным вариантом является использование Ruff + pre-commit. Ruff отвечает за проверку и форматирование кода, а pre-commit автоматически запускает эти проверки перед каждым Git-коммитом.

При необходимости проект можно дополнить `mypy`, тестами и другими инструментами статического анализа.
