# Poetry — управление зависимостями и сборка пакетов в Python

## 1. Что такое Poetry

**Poetry** — современный инструмент для управления зависимостями, виртуальными окружениями, сборкой и публикацией пакетов в экосистеме Python. Он объединяет функциональность, которая раньше распределялась между разными инструментами и файлами: `pip`, `venv`, `setuptools`, `twine`, `requirements.txt`, `setup.py`, `setup.cfg`.

Проект создан **Себастьеном Юстасом (Sébastien Eustace)**, развивается как open-source под лицензией MIT в организации **python-poetry** на GitHub.

Центральный элемент системы — единый файл **`pyproject.toml`** (стандарт PEP 517/518/621), где описаны метаданные проекта, зависимости, точки входа и параметры сборки. Дополняет его файл **`poetry.lock`**, фиксирующий точные версии всех пакетов — включая транзитивные (зависимости зависимостей) — для полной воспроизводимости окружения.

## 2. Что делает Poetry

- **Разрешение и установка зависимостей.** Poetry строит граф зависимостей, разрешает конфликты версий и устанавливает пакеты параллельно (в отличие от `pip`, устанавливающего последовательно).
- **Фиксация версий.** Все точные версии, включая транзитивные зависимости, записываются в `poetry.lock` — при установке на любой другой машине через `poetry install` гарантированно ставится идентичный набор пакетов.
- **Автоматическое управление виртуальными окружениями.** Poetry сам создаёт изолированное окружение под каждый проект, без ручного вызова `venv`.
- **Разделение зависимостей на группы.** Пакеты делятся на обязательные (production) и вспомогательные (`dev`, `test`, `docs` и т. д.) — последние не попадают в конечную поставку продукта.
- **Сборка и публикация пакетов.** Позволяет собирать `sdist`/`wheel` без `setup.py` и публиковать напрямую в PyPI или приватный репозиторий.
- **Диагностика проекта.** Команды для просмотра дерева зависимостей, устаревших версий, информации об окружении.
- **Скрипты и точки входа.** Настройка пользовательских команд через `[tool.poetry.scripts]`.
- **Расширяемость через плагины** (например, `poetry-plugin-export`, `poetry-plugin-shell`).

## 3. Где скачать и как установить

Официальный сайт: **https://python-poetry.org**
Репозиторий: **https://github.com/python-poetry/poetry**
Документация: **https://python-poetry.org/docs/**

### Способ 1 — pip 
```bash
pip install poetry
```

### Способ 2 — официальный скрипт-установщик 
**Windows (PowerShell):**
```powershell
(Invoke-WebRequest -Uri https://install.python-poetry.org -UseBasicParsing).Content | py -
```
**macOS/Linux:**
```bash
curl -sSL https://install.python-poetry.org | python3 -
```

### Способ 3 — pipx 
```bash
pipx install poetry
```

### Способ 4 — conda-forge
```bash
conda install -c conda-forge poetry
```

### Способ 5 — менеджеры пакетов ОС
- macOS (Homebrew): `brew install poetry`
- Linux (Snap): `snap install poetry --classic`

**Проверка установки:**
```bash
poetry --version
```

## 4. Виртуальные окружения: как Poetry их использует

Виртуальное окружение — изолированная копия Python с собственным набором установленных библиотек, отдельная для каждого проекта. Это исключает конфликты, когда разным проектам нужны разные версии одной и той же библиотеки, и защищает системный Python от засорения.

**Где хранятся окружения по умолчанию:**
- Linux/macOS: `~/.cache/pypoetry/virtualenvs/`
- Windows: `%APPDATA%\pypoetry\virtualenvs\` (либо `AppData\Local\pypoetry\Cache\virtualenvs`, в зависимости от версии)

**Хранить окружение внутри проекта** (папка `.venv` рядом с кодом — удобно для IDE и CI/CD):
```bash
poetry config virtualenvs.in-project true
```

Важно понимать разграничение: **код программы, `pyproject.toml` и `poetry.lock` хранятся в папке проекта**; **само виртуальное окружение (интерпретатор + установленные библиотеки) хранится отдельно**, вне проекта, и лишь логически привязано к нему.

## 5. Production- и dev-зависимости

- **Основные (production) зависимости** — необходимы для работы приложения. Без них программа не запустится. Пример: `requests` для HTTP-запросов.
- **Dev-зависимости** — нужны только на этапе разработки: тестирование (`pytest`), форматирование (`black`), линтинг (`flake8`, `pylint`). В продакшене они не устанавливаются.

**Современный синтаксис (Poetry 2.x, стандарт PEP 735):**
```toml
[project]
dependencies = [
    "requests (>=2.34.2,<3.0.0)"
]

[dependency-groups]
dev = [
    "pytest (>=9.1.1,<10.0.0)"
]
```

**Устаревший, но всё ещё поддерживаемый синтаксис (Poetry 1.x):**
```toml
[tool.poetry.dependencies]
requests = "^2.28.1"

[tool.poetry.group.dev.dependencies]
pytest = "^7.2.0"
```

**Добавление зависимости в группу разработки:**
```bash
poetry add pytest --group dev
# короткий алиас для группы dev:
poetry add pytest --dev
```

**Установка только production-зависимостей** (актуальный синтаксис; флаг `--no-dev` объявлен устаревшим):
```bash
poetry install --only main
```

## 6. Практические примеры команд

```bash
# Создание нового проекта с нуля
poetry new my-project

# Инициализация в существующей папке
poetry init

# Добавление production-зависимости
poetry add requests

# Добавление dev-зависимости
poetry add pytest --group dev

# Установка всех зависимостей проекта (по poetry.lock)
poetry install

# Установка только production-зависимостей (продакшен)
poetry install --only main

# Удаление зависимости
poetry remove requests

# Запуск команды внутри окружения проекта
poetry run python main.py

# Активация окружения в текущей оболочке
poetry shell

# Дерево зависимостей
poetry show --tree

# Проверка неактуальных версий
poetry show --latest

# Обновление зависимостей до последних разрешённых версий
poetry update

# Сборка пакета (sdist + wheel)
poetry build

# Публикация в PyPI
poetry publish

# Экспорт в классический requirements.txt
poetry export -f requirements.txt --output requirements.txt
```

## 7. Сравнение с классическим подходом (pip + requirements.txt)

| Критерий | Poetry | pip + requirements.txt |
|---|---|---|
| Управление окружением | Автоматическое | Ручное (`venv`) |
| Фиксация версий | `poetry.lock` (детерминированная, включая транзитивные) | `requirements.txt` (часто неполный) |
| Разделение зависимостей | Группы в одном файле (`dependency-groups`) | Отдельные файлы (`requirements-dev.txt`) |
| Установка пакетов | Параллельная | Последовательная |
| Дерево зависимостей | Встроенная команда `poetry show --tree` | Нет встроенного средства |
| Сборка пакета | Встроена (`poetry build`) | Требует ручной настройки `setup.py` |

## 8. Полный список команд Poetry

| Команда | Что делает |
|---|---|
| `poetry init` | Создаёт `pyproject.toml` в текущей папке через серию вопросов — для уже существующего проекта |
| `poetry new <название>` | Создаёт новый проект с нуля: папку, `pyproject.toml`, структуру каталогов и заготовку под тесты |
| `poetry add <пакет>` | Добавляет библиотеку в проект: находит подходящую версию, устанавливает и обновляет `pyproject.toml` + `poetry.lock` |
| `poetry add <пакет> --group dev` | Добавляет библиотеку в группу разработки (не попадает в продакшен-поставку) |
| `poetry remove <пакет>` | Удаляет библиотеку из проекта и окружения |
| `poetry install` | Устанавливает все зависимости проекта согласно `poetry.lock` (при первом запуске или после `git clone`) |
| `poetry install --only main` | Устанавливает только production-зависимости, без dev-групп (для продакшен-сервера) |
| `poetry update` | Обновляет зависимости до последних версий, разрешённых ограничениями в `pyproject.toml`, пересчитывает `poetry.lock` |
| `poetry show` | Показывает список всех установленных зависимостей и их версий |
| `poetry show --tree` | Показывает зависимости в виде дерева — видно, что от чего зависит |
| `poetry show --latest` | Сравнивает установленные версии с последними доступными, подсвечивает несовпадения |
| `poetry run <команда>` | Выполняет команду внутри виртуального окружения проекта, без его активации |
| `poetry shell` | Активирует виртуальное окружение проекта в текущем терминале |
| `poetry env use <путь/версия>` | Указывает Poetry, какой именно интерпретатор Python использовать для окружения |
| `poetry env list` | Показывает список виртуальных окружений, связанных с проектом |
| `poetry env info` | Показывает путь к окружению, версию Python, используемый интерпретатор |
| `poetry env remove <имя>` | Удаляет указанное виртуальное окружение |
| `poetry build` | Собирает пакет проекта в форматы `sdist` (архив исходников) и `wheel` (готовый к установке пакет) |
| `poetry publish` | Публикует собранный пакет в PyPI (или в приватный репозиторий) |
| `poetry check` | Проверяет корректность файла `pyproject.toml` |
| `poetry lock` | Пересоздаёт `poetry.lock` без установки пакетов (после ручного редактирования `pyproject.toml`) |
| `poetry export -f requirements.txt --output requirements.txt` | Экспортирует зависимости в классический формат `requirements.txt` |
| `poetry config --list` | Показывает текущие настройки конфигурации Poetry |
| `poetry config virtualenvs.in-project true` | Настраивает создание `.venv` внутри папки проекта, а не в общем кэше |
| `poetry cache clear <репозиторий> --all` | Очищает локальный кэш скачанных пакетов |
| `poetry --version` | Показывает установленную версию самого Poetry |
