# Виртуальные окружения Python

## Введение

Python — один из самых популярных языков программирования. С его помощью создают сайты, Telegram-ботов, игры, программы для анализа данных, искусственный интеллект и множество других проектов.

Однако при разработке на Python программист довольно быстро сталкивается с одной проблемой: **разные проекты могут требовать разные версии библиотек**.

Например, представим, что у нас есть два проекта:

- первый использует `Django 4.2`;
- второй требует `Django 5.2`.

Если установить всё в одну общую среду Python, версии библиотек могут конфликтовать. Обновление библиотеки для одного проекта способно сломать другой.

Именно для решения этой проблемы существуют **виртуальные окружения Python**.

> **Виртуальное окружение — это изолированная среда Python, в которой проект хранит собственные библиотеки и их версии, не вмешиваясь в другие проекты.**

## 1. Зачем вообще нужны виртуальные окружения?

Чтобы понять идею виртуального окружения, представим компьютер, на котором находятся три Python-проекта:

```
Мой компьютер
│
├── Проект №1 — сайт
│   └── Django 4.2
│
├── Проект №2 — интернет-магазин
│   └── Django 5.2
│
└── Проект №3 — анализ данных
    └── pandas, numpy, matplotlib
```

Если все библиотеки устанавливать глобально, получается примерно такая ситуация:

```
Глобальный Python
│
├── Django 4.2
├── Django 5.2   ← конфликт!
├── pandas
├── numpy
├── matplotlib
└── ещё десятки библиотек
```

Python не может одновременно использовать две несовместимые версии одной и той же библиотеки в одном окружении.

Виртуальные окружения решают проблему:

```
Проект №1
└── .venv
    └── Django 4.2

Проект №2
└── .venv
    └── Django 5.2

Проект №3
└── .venv
    ├── pandas
    ├── numpy
    └── matplotlib
```

Теперь каждый проект получает собственный набор зависимостей.

## 2. Что такое `venv`?

В стандартной установке Python уже существует инструмент для создания виртуальных окружений — `venv`.

Создать окружение можно одной командой:

```bash
python -m venv .venv
```

Здесь:

- `python` — запускает Python;
- `-m venv` — говорит Python использовать модуль `venv`;
- `.venv` — название папки, в которой будет находиться виртуальное окружение.

Название `.venv` не является обязательным. Можно написать, например:

```bash
python -m venv my_environment
```

Но `.venv` — очень распространённое соглашение.

## 3. Как выглядит виртуальное окружение?

После выполнения команды `python -m venv .venv` в проекте появится папка:

```
my_project/
│
├── .venv/
│   ├── Scripts/       # Windows
│   ├── Lib/
│   └── ...
│
└── main.py
```

На Linux и macOS структура немного отличается:

```
my_project/
│
├── .venv/
│   ├── bin/
│   ├── lib/
│   └── ...
│
└── main.py
```

Внутри окружения находятся необходимые файлы для запуска Python и установки пакетов.

## 4. Как активировать виртуальное окружение?

Создать окружение недостаточно. Перед работой с ним обычно нужно его **активировать**.

### Windows

В командной строке:

```bash
.venv\Scripts\activate
```

В PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

После активации в терминале можно увидеть:

```
(.venv) C:\Projects\my_project>
```

Слово `(.venv)` показывает, что виртуальное окружение активно.

### Linux и macOS

Используется команда:

```bash
source .venv/bin/activate
```

После этого:

```
(.venv) user@computer:~/my_project$
```

## 5. Что происходит после активации?

Теперь команды `python` и `pip` будут использовать окружение проекта.

Например:

```bash
pip install requests
```

установит библиотеку `requests` именно в наше виртуальное окружение.

Можно проверить установленные библиотеки:

```bash
pip list
```

## 6. Что такое `pip`?

`pip` — стандартный инструмент Python для установки сторонних пакетов:

```bash
pip install requests
```

После этого в программе можно написать:

```python
import requests

response = requests.get("https://example.com")
print(response.status_code)
```

Виртуальное окружение и `pip` очень часто используются вместе:

```
Python → venv → pip → Библиотеки проекта
```

## 7. Файл `requirements.txt`

Мы сделали проект и установили несколько библиотек. А что, если отправить проект другу?

Папку `.venv` передавать не нужно. Вместо этого сохраняют список зависимостей:

```bash
pip freeze > requirements.txt
```

Например:

```
requests==2.32.3
urllib3==2.2.2
certifi==2024.7.4
```

Другой разработчик может воссоздать такое же окружение:

```bash
python -m venv .venv
source .venv/bin/activate        # или .venv\Scripts\activate на Windows
pip install -r requirements.txt
```

## 8. Почему нельзя просто отправить папку `.venv`?

Виртуальное окружение привязано к конкретному компьютеру, ОС и пути к Python. Windows, Linux и macOS различаются.

Поэтому обычно делают так:

```
project/
├── .venv/          ← НЕ отправляем
├── main.py
├── requirements.txt
└── README.md
```

А `.venv` добавляют в `.gitignore`.

## 9. `.gitignore`

Если проект хранится в Git, виртуальное окружение обычно не загружают в репозиторий. Для этого в `.gitignore` добавляют:

```
.venv/
```

Теперь Git будет игнорировать эту папку.

## 10. Как выйти из виртуального окружения?

Когда работа закончена, выполните:

```bash
deactivate
```

## 11. Как удалить виртуальное окружение?

`venv` можно просто удалить как обычную папку:

```bash
rm -rf .venv          # Linux/macOS
rmdir /s /q .venv     # Windows
```

После этого окружение можно создать заново и восстановить библиотеки из `requirements.txt`. Это одна из приятных особенностей виртуальных окружений: **их не страшно пересоздавать**.

## 12. Типичная ошибка новичков

```bash
pip install requests
python main.py        # ModuleNotFoundError: No module named 'requests'
```

Почему? Возможно, `pip` установил библиотеку в один Python, а команда `python` запускает другой:

```
pip    → Python №1
python → Python №2
```

Чтобы избежать этого, используйте:

```bash
python -m pip install requests
```

Тогда мы явно говорим: «Используй `pip`, принадлежащий именно этому Python».

## 13. Альтернативы `venv`

Существуют и другие инструменты управления окружениями и зависимостями:

- `virtualenv`;
- `Poetry`;
- `Pipenv`;
- `Conda`;
- современные менеджеры проектов, такие как `uv`.

Но `venv` особенно хорош для начала обучения:

1. встроен в Python;
2. не требует отдельной установки;
3. прост в использовании;
4. подходит для большинства небольших и учебных проектов.

## Заключение

Виртуальное окружение — это «личное пространство» Python-проекта, где его зависимости могут жить спокойно и не мешать остальным проектам. Для начинающего самое главное — привыкнуть создавать окружение для каждого нового проекта:

```bash
python -m venv .venv
```

## Краткая памятка

| Действие | Команда |
|---|---|
| Создать окружение | `python -m venv .venv` |
| Активировать Windows | `.venv\Scripts\activate` |
| Активировать Linux/macOS | `source .venv/bin/activate` |
| Установить пакет | `python -m pip install package` |
| Посмотреть пакеты | `pip list` |
| Сохранить зависимости | `pip freeze > requirements.txt` |
| Установить зависимости | `pip install -r requirements.txt` |
| Выйти | `deactivate` |
