# Astral uv: Практический гайд и Get Started для разработчика

> **Что это:** Компактный доклад-гайд по современному менеджеру пакетов и проектов в Python.  
> **Время чтения:** ~10 минут.  
> **Для кого:** Студенты, Python-разработчики

---

## 1. Что такое `uv` и какую проблему он решает?

Исторически разработка на Python страдала от **зоопарка разрозненных инструментов**:
* Пакеты ставили через `pip`.
* Окружения создавали через `virtualenv` или `venv`.
* Зависимости фиксировали через `pip-tools` или тяжёлый `Poetry`.
* Версии самого Python переключали через `pyenv`.
* Консольные утилиты запускали изолированно через `pipx`.

Каждый инструмент имел свои команды, свои баги и работал невыносимо медленно. Установка пачки тяжелых библиотек (`pandas`, `torch`, `scipy`) в новый проект могла занимать 5–10 минут.

### В чём революция `uv`?
**`uv`** — это проект от компании **Astral** (создателей самого быстрого Python-линтера `Ruff`). Он написан на **Rust** и объединяет все эти 5 утилит в **один легковесный бинарный файл**.

**Ключевые фичи:**
1. **Скорость в 10–100 раз выше `pip`:** Установка библиотек занимает миллисекунды, а не минуты.
2. **Умный глобальный кэш (Hardlinks):** Если библиотека уже скачана на компьютер один раз, `uv` не качает и не копирует её заново в каждый новый проект, а мгновенно связывает её через жесткие ссылки (hardlinks). Диск не забивается дубликатами.
3. **Управление версиями Python:** `uv` сам умеет скачивать и ставить нужные версии Python (3.10, 3.11, 3.12, 3.13) без необходимости ставить `pyenv` или лезть на python.org.
4. **Бесшовная изоляция (`uv run`):** Больше не нужно вручную писать `source .venv/bin/activate`! Команда `uv run` автоматически запускает скрипт внутри нужного окружения.
5. **Современные стандарты (PEP 621, PEP 723, PEP 735):** Поддерживает единый формат конфигурации `pyproject.toml` и детерминированный lock-файл `uv.lock`.

## 2. Установка за 10 секунд

`uv` распространяется как один готовый бинарник и не требует установленного Python для своей работы:

* **В Linux, macOS и WSL (Ubuntu):**
  ```bash
  curl -LsSf https://astral.sh/uv/install.sh | sh
  ```
* **В Windows (PowerShell):**
  ```powershell
  powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
  ```
* **Проверка установки:**
  ```bash
  uv --version
  # Пример вывода: uv 0.9.9
  ```

## 3. Топ-10 ключевых команд uv (Шпаргалка на каждый день)

| № | Команда | Что делает простыми словами |
|---|---|---|
| 1 | `uv init my_project` | Создает структуру нового Python-проекта с `pyproject.toml` и `.python-version`. |
| 2 | `uv add <пакет>` | Добавляет библиотеку в проект, обновляет `pyproject.toml` и фиксирует версии в `uv.lock`. |
| 3 | `uv remove <пакет>` | Удаляет библиотеку из зависимостей и виртуального окружения. |
| 4 | `uv run <команда/скрипт>` | Запускает код в виртуальном окружении **без ручной активации**. Если окружения нет — создаст на лету! |
| 5 | `uv sync` | Приводит виртуальное окружение в строгое соответствие с `uv.lock` (удалит лишнее, доставит нужное). |
| 6 | `uv lock` | Вычисляет граф зависимостей и генерирует кроссплатформенный `uv.lock`. |
| 7 | `uv python install 3.12` | Скачивает и ставит автономную сборку Python нужной версии. |
| 8 | `uv python pin 3.12` | Привязывает текущий проект к конкретной версии Python (создает `.python-version`). |
| 9 | `uv pip install -r requirements.txt` | Drop-in замена старому доброму `pip`, но работает со скоростью света. |
| 10 | `uvx <утилита>` | Запускает автономную CLI-утилиту (Ruff, Black, Mypy) без захламления проекта. |

## 4. Три главных рабочих сценария (Get Started)

### Сценарий А: Создание нового проекта с нуля (Современный подход)

```bash
# 1. Инициализируем проект
uv init my_fast_app
cd my_fast_app

# 2. Добавляем библиотеки (например, FastAPI и requests)
uv add fastapi uvicorn requests

# 3. Добавляем инструмент для разработки в dev-группу
uv add --dev pytest

# 4. Запускаем код! Не нужно активировать venv вручную!
uv run main.py
```
> **Что произошло под капотом:** `uv` автоматически создал `.venv`, установил зависимости за доли секунды, записал их в `pyproject.toml` и сгенерировал надежный `uv.lock`.

---

### Сценарий Б: Ускорение старого проекта с `requirements.txt`

Если у тебя уже есть существующий проект со старым файлом `requirements.txt`:

```bash
cd /path/to/legacy_project

# Вариант 1: Использовать как ультрабыстрый pip
uv venv                       # Создать .venv за 15 миллисекунд
uv pip install -r requirements.txt   # Поставить зависимости в 20 раз быстрее pip

# Вариант 2: Мигрировать на современный uv-проект
uv init --bare                # Добавить pyproject.toml в текущую папку
uv add -r requirements.txt    # Перенести все зависимости в pyproject.toml и uv.lock
```

---

### Сценарий В: Запуск однофайлового скрипта «на коленке» (PEP 723)

Бывает нужно написать один небольшой скрипт для парсинга или выгрузки данных, ради которого лень создавать целый проект и виртуальное окружение:

```bash
# Мгновенный запуск скрипта с временной подгрузкой библиотеки:
uv run --with httpx python3 -c "import httpx; print(httpx.get('https://httpbin.org/get').status_code)"
```

Или добавить метаданные прямо в шапку `.py` файла (стандарт PEP 723):
```python
# /// script
# requires-python = ">=3.11"
# dependencies = [
#     "httpx",
#     "rich",
# ]
# ///

import httpx
from rich import print

resp = httpx.get("https://httpbin.org/json")
print(resp.json())
```
Запуск: `uv run script.py`. `uv` сам прочитает шапку, создаст изолированное временное окружение и запустит скрипт!

## 5. Анатомия `pyproject.toml` и `uv.lock` на пальцах

Файл `pyproject.toml` — это современный единый паспорт любого Python-проекта (стандарты PEP 518 и PEP 621). Он пришел на смену устаревшим `setup.py`, `setup.cfg` и `requirements.txt`.

### Пример живого файла `pyproject.toml` в проекте uv:

```toml
[project]
name = "fastapi-service"
version = "0.1.0"
description = "Учебный микросервис на FastAPI"
readme = "README.md"
requires-python = ">=3.12"      # Минимальная версия Python, uv сам её проверит и скачает
dependencies = [                # Боевые зависимости (production)
    "fastapi>=0.115.0",
    "pydantic>=2.9.0",
    "uvicorn[standard]>=0.31.0",
]

[dependency-groups]             # Разделение зависимостей по стандарту PEP 735
dev = [                         # Инструменты разработки (не попадут в прод-образ)
    "pytest>=8.3.0",
    "pytest-cov>=5.0.0",
    "ruff>=0.6.0",
]
docs = [                        # Дополнительная группа (например, для сборки документации)
    "mkdocs>=1.6.0",
]

[build-system]                  # Сборщик проекта (если проект упаковывается в wheel)
requires = ["hatchling"]
build-backend = "hatchling.build"

[tool.uv]                       # Персональные настройки uv для проекта
# Здесь можно переопределить источники PyPI-зеркал или параметры сборки
```

### Как управлять зависимостями в `pyproject.toml` через консоль:
* Добавить боевой пакет в `dependencies`:
  ```bash
  uv add fastapi
  ```
* Добавить инструмент в группу разработки `dev`:
  ```bash
  uv add --dev pytest ruff
  ```
* Добавить пакет в кастомную группу (`--group`):
  ```bash
  uv add --group docs mkdocs
  ```

---

### `pyproject.toml` против `uv.lock`: в чём разница?

| Файл | Для кого создан | Что содержит | Нужно ли коммитить в Git? |
|---|---|---|:---:|
| **`pyproject.toml`** | **Для человека** | Верхнеуровневые правила и свободные диапазоны версий (например, `fastapi>=0.115.0`). Пишется руками или через `uv add`. | **ДА (Всегда)** |
| **`uv.lock`** | **Для машины** | Точный слепок всего дерева транзитивных зависимостей (включая все подзависимости), фиксированные версии и криптографические SHA-256 хэши для безопасности. | **ДА (Обязательно)** |

> 💡 **Золотое правило:** `pyproject.toml` декларирует **требования** разработчика («мне нужен FastAPI версии не ниже 0.115»), а `uv.lock` фиксирует **точный воспроизводимый слепок** окружения. Благодаря этому команда `uv sync` на компьютере одногруппника или сервере установит ровно те же файлы, байт-в-байт.

## 6. Сравнение: `uv` против `pip` и `Poetry`

| Критерий | `pip` + `venv` | `Poetry` | `Astral uv` |
|---|---|---|---|
| **Язык реализации** | Python | Python | **Rust (Скомпилированный бинарник)** |
| **Скорость установки** | Медленно (1x) | Медленно–средне (0.8x–1.5x) | **Экстремально быстро (10x–100x)** |
| **Управление версиями Python** | Нет (нужен pyenv) | Нет (нужен pyenv) | **Да (`uv python install`)** |
| **Ручная активация окружения** | Обязательна (`source bin/activate`) | `poetry shell` / `run` | **Не нужна (`uv run`)** |
| **Экономия места на диске** | Нет (каждый venv дублирует файлы) | Нет (дубликаты файлов) | **Да (глобальный кэш + hardlinks)** |
| **Поддержка legacy `requirements.txt`** | Да | Частично | **Да, полная (`uv pip`)** |

## 7. Топ-5 ошибок и граблей новичков

1. **Привычка по старинке активировать окружение:**
   * *Ошибка:* Постоянно писать `source .venv/bin/activate`, путаться в версиях и окружениях.
   * *Как правильно:* Забудь про активацию! Просто запускай команды через `uv run pytest`, `uv run python script.py`.

2. **Смешивание `uv pip install` и `uv add`:**
   * *Ошибка:* В проекте с `pyproject.toml` вызывать `uv pip install pandas`.
   * *Почему это плохо:* `uv pip` ставит пакет втихую в venv, но **не сохраняет** его в `pyproject.toml` и `uv.lock`. При следующем `uv sync` пакет пропадет.
   * *Как правильно:* В проектах всегда используй `uv add <пакет>`. Команду `uv pip` оставляй только для старых скриптов и Docker-образов.

3. **Забыть добавить `uv.lock` в Git:**
   * *Ошибка:* Добавлять `uv.lock` в `.gitignore`.
   * *Как правильно:* `uv.lock` **ОБЯЗАТЕЛЬНО** должен быть в Git репозитории! Именно он гарантирует, что у твоих коллег и на сервере установятся версии библиотек бит-в-бит одинаковые с твоими.

4. **Ручное редактирование версий в `pyproject.toml`:**
   * *Ошибка:* Поменять строку в `pyproject.toml` руками и сразу запускать код.
   * *Как правильно:* После ручной правки обязательно выполни `uv lock` или `uv sync`, чтобы обновился lock-файл.
