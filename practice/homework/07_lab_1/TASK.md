## А1. Перцептрон (однослойная нейросеть для классификации)

### А1.1 Общее описание
Перцептрон — простейшая модель нейросети: принимает признаки, **умножает на веса**,
**суммирует** и пропускает через **функцию активации** (порог), выдавая класс
(например, `0` или `1`). Обучается по правилу: если ошибся — подправляем веса.

### А1.2 Что должно быть в программе
1. **Класс `Perceptron`**:
   - `__init__(self, n_features, learning_rate=0.1, epochs=...)`;
   - веса `w` (список/массив чисел) + порог (bias);
   - `predict(x)` — сумма `Σ w_i·x_i + bias`, затем порог → `0/1`;
   - `train(X, y)` — цикл по эпохам, правило обновления весов `w += lr·(target − pred)·x`;
   - `score(X, y)` — доля правильных ответов.

2. **Синтетический набор данных** (2D, линейно разделимые классы):
   - два класса, генерируемых случайно (например, вокруг двух разных центров);
   - визуализация границы решения через `matplotlib` — **обязательно** (см. А1.5).

3. **CLI**:
   ```
   python perceptron.py --samples 200 --lr 0.1 --epochs 50
   ```
   - генерирует данные, обучает перцептрон, печатает итоговую точность.

### А1.3 Обязательные функции/методы (каркас)
```
Perceptron
 ├── __init__(n_features, learning_rate, epochs)
 ├── activate(z)         # пороговая функция: 1 если z>=0 иначе 0
 ├── predict(x)          # шаг forward: сумма, активация
 ├── train(X, y)         # цикл обучения
 └── score(X, y)         # точность (доля верных)
```

### А1.4 Что проверяют тесты
- `activate`: порог срабатывает правильно (например `activate(0)=1`, `activate(-1)=0`);
- `predict` на идеально разделимых данных даёт правильный класс;
- **обучение разделяет** два линейно-разделимых класса (score ~ 1.0 после обучения);
- инициализация весов — массив ожидаемой длины.

### А1.5 Обязательные визуализации и расширения
- Визуализация границы решения через `matplotlib` (расцветить точки классов и линию решения).
- Функция потерь / график ошибок по эпохам (как убывает ошибка при обучении).
- Проверка на **реальном** наборе данных (iris из `sklearn` или его локальная копия).

## А2. Метод k-средних (кластеризация)

### А2.1 Общее описание
Алгоритм разбивает данные на **k групп (кластеров)** по близости к центрам.
Работает итеративно: 1) назначаем точки ближайшему центру, 2) пересчитываем
центры как среднее точек кластера. Повторяем, пока центры не сойдутся.

### А2.2 Что должно быть в программе
1. **Функции/класс `KMeans`**:
   - `__init__(n_clusters=3, max_iter=100, seed=...)`;
   - `fit(X)` — обучает: инициализация центров, итерации, возвращает метки;
   - `predict(X)` — для новых точек вернуть ближайший кластер;
   - `inertia` (СКО внутри кластеров) — критерий качества;
   - **генерируемые тестовые данных** (например, 3 «кластера» вокруг центров).

2. **CLI**:
   ```
   python kmeans.py --samples 300 --k 3 --iter 100 --seed 42
   ```
   - генерирует данные, кластеризует, печатает число точек в кластерах + inertia.

### А2.3 Обязательные элементы
```
KMeans
 ├── __init__(k, max_iter, seed)
 ├── _init_centroids(X)   # начальные центры (случайно, фикс. seed)
 ├── _assign(X)           # каждой точке — ближайший центр
 ├── _update(X, labels)   # пересчёт центров = среднее точек
 ├── fit(X)               # итерации до сходимости
 ├── predict(X)
 └── inertia(X, labels)   # сумма квадратов расстояний до своих центров
```

### А2.4 Что проверяют тесты
- На данных, сгенерированных вокруг **3 известных центров**, k=3 находит кластеры
  (после обучения метки близки к ожидаемым перестановкой кластеров);
- `inertia` не увеличивается при росте итераций (монотонность);
- одинаковые `seed` → одинаковые результаты (воспроизводимость);
- разные `k` → разное число кластеров.

### А2.5 Обязательные визуализации и расширения
- Визуализация кластеров через `matplotlib` (расцветить точки по кластерам и отметить центры).
- Метод «локтя» (elbow): поиск оптимального `k` по графику inertia — команда `--elbow`.
- Реализация на **чистом Python** (списки), без `numpy` в ядре алгоритма — показать понимание, а не готовый `sklearn.cluster.KMeans`.

## Б1. Менеджер паролей (в терминале)

### Б1.1 Общее описание
Консольное приложение для хранения и управления паролями: вход по мастер-паролю,
добавление/поиск/удаление записей, скрытый ввод пароля.

### Б1.2 Что должно быть в программе
1. **Вход по мастер-паролю**:
   - при первом запуске — создать мастер-пароль и сохранить его проверочный хэш;
   - при повторном — запросить пароль, сравнить хэш (SHA-256 / PBKDF2), пустить внутрь;
   - не хранить пароль в открытом виде. **Только хэш.**

2. **Управление записями** (сервис/имя + логин/пароль):
   - `add` — добавить запись;
   - `list` — показать названия (НЕ сами пароли);
   - `get <name>` — показать пароль (после подтверждения мастер-паролем);
   - `delete <name>` — удалить;
   - данные хранятся в файле (JSON), пароли дополнительно **зашифрованы**
     (например, простой XOR/соль либо библиотека `cryptography`).

3. **Скрытый ввод пароля**:
   - при вводе мастер-пароля символы не отображаются (или показываются `*`);
   - реализация: `getpass` в стандартной библиотеке.

4. **CLI-интерфейс** (интерактивное меню ИЛИ аргументы):
   ```
   python password_manager.py --init          # создать мастер-пароль
   python password_manager.py --unlock        # вход
   # далее меню: add / list / get / delete / exit
   ```

### Б1.3 Обязательные функции
```
PasswordManager
 ├── init_master(password)     # создать хэш мастера
 ├── unlock(password) -> bool  # проверка хэша
 ├── add_entry(name, login, pwd)
 ├── list_entries() -> list[str]
 ├── get_entry(name) -> login/pwd
 ├── delete_entry(name)
 └── _persist() / _load()      # сохранение и чтение (JSON+соль)
```

### Б1.4 Что проверяют тесты
- `unlock` с верным паролем → `True`, с неверным → `False`;
- инициализация один раз, повторный `--init` не может перезаписать без пароля;
- `add` → `list` показывает имя, `get` возвращает пароль;
- `delete` убирает запись;
- в хранилище пароль/мастер **не хранятся открыто** (проверка хэша/шифра).

### Б1.5 Обязательные расширения безопасности
- Генератор новых надёжных паролей (`--generate`) — символы, цифры, спецсимволы.
- Соль при хэшировании мастер-пароля (случайная соль на пользователя).
- Шифрование сохранённых записей симметричным алгоритмом (например, через `cryptography`), а не только хэширование мастер-пароля.

## Б2. Змейка (консольная игра)

### Б2.1 Общее описание
Классическая игра «Змейка» в терминале: змейка растёт, поглощая еду; при столкновении
с собой или стеной — проигрыш. Управление — стрелками, поле перерисовывается на месте.

### Б2.2 Что должно быть в программе
1. **Классы**:
   - `Snake` — тело (список сегментов), направление, рост, проверка самопересечения;
   - `Game` — поле, еда, цикл, счёт, состояние (игра идёт / Game Over).

2. **Логика**:
   - движение каждые `tick` секунд;
   - еда появляется в случайной свободной клетке;
   - поедание еды = рост + счёт;
   - столкновение со стеной или собой = конец игры;
   - счёт и уровень (ускорение при росте счёта — см. Б2.5).

3. **Отображение**:
   - поле рисуется в терминале **на месте** (ANSI `\033[H`, `\r\n`), не спамит;
   - управление стрелками — **raw-режим ввода** (termios/tty) либо `getch`-аналог.

4. **Запуск**:
   ```
   python snake.py --width 20 --height 15 --speed 8
   ```

### Б2.3 Обязательные классы/методы
```
Snake
 ├── __init__(start_pos, direction)
 ├── move(dx, dy)
 ├── grow()              # удлинение при поедании
 ├── head()              # текущая позиция головы
 ├── collides_self() -> bool
 └── body                # список сегментов

Game
 ├── __init__(w, h, speed)
 ├── spawn_food()
 ├── step(direction)     # один шаг логики
 ├── is_over -> bool
 └── score
```

### Б2.4 Что проверяют тесты (БЕЗ реального ввода!)
- `Snake.move` корректно меняет позицию головы;
- поедание еды увеличивает длину;
- `collides_self` = True при самопересечении;
- столкновение со стеной = конец игры;
- `spawn_food` всегда в свободной клетке.

> Важно: логика движения/столкновений должна быть **выделена** так, чтобы её можно
> было тестировать без самого терминала и клавиатуры.

### Б2.5 Обязательные игровые расширения
- Уровни и ускорение: счёт растёт → скорость падения растёт, уровень отображается.
- Режим «пауза» (клавиша, останавливает игру).
- Итоговый экран Game Over со счётом и предложением сыграть ещё раз.
