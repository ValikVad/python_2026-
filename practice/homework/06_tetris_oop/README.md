# 06 · ООП через Тетрис — две версии

Урок по **объектно-ориентированному программированию** на примере Тетриса:
базовый класс `Figure` + семь наследников. Здесь лежат **две версии** — рабочая
и для самостоятельного дописывания.

## 📁 Структура папки

```
06_тетрис_ооп/
├── README.md        ← этот файл (карточка урока)
├── solution/         ← ПОЛНАЯ рабочая версия (эталон)
│   ├── figures.py   ← базовый Figure + 7 наследников
│   ├── tetris.py    ← консольная игра (перерисовка на месте)
│   └── tests/       ← 25 тестов: юнит + функциональные
│
└── student/        ← версия для студентов (нужно ДОПИСАТЬ)
    ├── TASK.md   ← что сделать, принципы ООП
    ├── figures.py   ← ❌ каркас с TODO(студент)
    ├── tetris.py    ← ✅ работает как есть (использует фигуры)
    ├── conftest.py  ← для запуска тестов локально
    └── tests/       ← те же тесты (падают, пока не допишешь)
```

## 🤔 Зачем две версии

- **`solution/`** — «как должно быть». Пользуйся как эталоном проверки, ответами,
  справочником по ООП. Все проверки (pytest/mypy/ruff) в CI проходят именно по нему.
- **`student/`** — «как раздать». Код игры работает, но `figures.py` — **недописан**:
  пустые `TODO(студент)`, `raise NotImplementedError`, неполный `ALL_FIGURES`.
  Студент восстанавливает ООП, а тесты подтверждают, что сделал правильно.

## 🎯 Принципы ООП, которые тренирует задание

- **Базовый класс** — общая логика в `Figure` (поворот, `cells`, `__eq__`).
- **Наследование** — наследники `class FigureI(Figure)` переиспользуют методы базы.
- **`super().__init__`** — делегирование конструктору родителя.
- **Полиморфизм** — `rotated()` возвращает экземпляр того же подкласса (`type(self)`);
  `Board` и `Tetris` работают с любой фигурой через общий интерфейс.
- **Атрибуты класса** — `COLOR`/`SYMBOL` общие для всех экземпляров.
